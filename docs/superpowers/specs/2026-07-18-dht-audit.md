# DHT crate audit — findings and fix list

Date: 2026-07-18
Scope: `dht/` (crate `midwest_mainline`), audited against BEP 5 + standard Kademlia.
All critical items hand-verified in code; minor items as reported (each cites its location).

**Status (2026-07-18, branch `dht-fix-everything`): all items addressed.** 4.1 (k-bucket
size) was resolved by documenting the deliberate deviation, per its own "fix or document"
option. Post-fix the crate was restructured: `dht_handle.rs` split into
`client.rs`/`server.rs`/`state.rs`. The SQL-free-routing-core refactor was consciously
skipped: SQLite-as-single-source-of-truth is a coherent design and in-memory sqlite pools
already back all router tests.

Legend: **[C]** correctness/protocol, **[P]** panic/robustness, **[L]** leak/resource, **[m]** minor.

## Tier 1 — remotely triggerable panics (one packet kills the whole DHT)

Parsing runs inline in the single broker receive loop (`krpc_broker.rs:89`), so any panic
kills all DHT I/O; `run()`'s result is discarded at `dht.rs:244` so nobody notices.

- [x] 1.1 **[P]** `NodeId::from_bytes` / `InfoHash::from_bytes` panic on wire ids ≠ 20 bytes
  (`types.rs:31-39`, `types.rs:95-101`). Fix: return a decode error instead of panicking.
- [x] 1.2 **[P]** `extract_peers`: non-6-byte `values` entries log but don't skip, then index
  `[0..6]` (`message.rs:223-232`). Fix: add the missing `return None` / filter them out.
- [x] 1.3 **[P]** `assert!(unused.len() == 0)` panics on trailing bytes after the dict
  (`message.rs:271`). Fix: decode error.
- [x] 1.4 **[P]** `closest_eight[0]` panics when the routing table is empty
  (`dht_handle.rs:128`). Fix: handle empty; also ensure empty responses still emit
  `nodes: ""` (BEP 5 requires the key).
- [x] 1.5 **[P]** `socket.recv_from(...).await.unwrap()` in the broker loop
  (`krpc_broker.rs:87`); macOS/BSD returns `ECONNREFUSED` after ICMP port-unreachable.
  Fix: log and continue. Same for `send_to(...).unwrap()` (`krpc_broker.rs:160`).
- [x] 1.6 **[P]** `rx.await.unwrap()` in `send_and_wait` (`krpc_broker.rs:172`) panics if
  the pending entry was evicted by a reused txn id. Fix: map to error.

## Tier 2 — protocol correctness (the DHT gives wrong answers)

- [x] 2.1 **[C]** `find_closest` returns nodes closest to *us*, not the target: centers the
  bucket scan on `self.index(&self.id)` (always 159) and sorts by distance to our own id
  (`router.rs:155`, `router.rs:185-190`). Fix: center on `self.index(&target)`, sort by
  `cmp_resp(..., target)`.
- [x] 2.2 **[C]** `get_peers` no-peers fallback returns nodes closest to the *querier*
  (`dht_handle.rs:184`); BEP 5 requires closest to the *info_hash*. Fix: pass the
  info_hash (as a NodeId) to `find_closest`.
- [x] 2.3 **[C]** Tokens bound to claimed node id, not requester IP
  (`token_generator.rs:26-35`, issuance `dht_handle.rs:175`, verify `dht_handle.rs:197-200`).
  BEP 5: token must be accepted only for the IP it was issued to. Fix: key the hash on
  the source `SocketAddrV4` ip (and keep the rotation scheme).
- [x] 2.4 **[C]** Iterative `find_node` bookkeeping: the `queried` set is populated once and
  never consulted/updated (same nodes re-queried each round); compares distance-to-us
  against a distance-to-target threshold; results not deduped (`dht_handle.rs:282-351`).
  Fix: update `queried` per round, select by distance to target, dedupe.
- [x] 2.5 **[C]** Client `get_peers` is one non-iterative round, never follows `nodes`
  referrals, and discards tokens so the caller can't `announce_peer` afterwards
  (`dht_handle.rs:406-437`). Fix: make it iterative like find_node; return tokens to the
  caller. (Blocks actually *using* the DHT from the downloader.)
- [x] 2.6 **[C]** Peers learned from others' `get_peers` responses are stored with a fresh
  timestamp as if announced to us (`dht_handle.rs:383-391`). BEP 5 stores peers only on a
  valid `announce_peer`. Fix: don't persist second-hand peers (keep them for the lookup
  result only).

## Tier 3 — resource leaks and staleness

- [x] 3.1 **[L]** `reply()` waits for a response to our response, with `Duration::MAX`
  (`krpc_broker.rs:208-217`, caller `dht_handle.rs:90-93`) — every inbound query leaks a
  task + pending entry forever. Fix: replies are fire-and-forget (`send_msg_background`).
- [x] 3.2 **[L]** Timed-out requests never remove their `pending_requests` entry
  (`krpc_broker.rs:183-198`). Fix: remove on timeout (and on send error).
- [x] 3.3 **[m]** Responses matched by txn id alone; ids are a `u32` counter from 0
  (`txn_id_generator.rs`) and source address is ignored. Fix: also match the responder's
  address; randomize txn ids.
- [x] 3.4 **[m]** Eviction is dead code: `failed_requests` is only ever reset, never
  incremented, so `replacement_queue` stays empty and dead nodes are never evicted
  (`router.rs:296,361,366,388`). Fix: increment on query timeout to that node.
- [x] 3.5 **[m]** Persisted `node.bucket` values go stale when our node id changes on IP
  change (`dht.rs:126-131`, computed at `router.rs:380-384`). Fix: recompute or clear
  bucket assignments on identity change.

## Tier 4 — minor / spec nits

- [x] 4.1 **[m]** k-bucket size is 1024 with no splitting rule (`router.rs:51`); BEP 5 says
  k = 8 with split-when-covers-self. Documented simplification — decide: fix or document.
- [x] 4.2 **[m]** No 204 Method Unknown for unknown query types (dead code:
  `message/error.rs:37-42`). Fix: reply 204 instead of just logging.
- [x] 4.3 **[m]** `announce_peer` port truncated via `as u16` (`message.rs:160`). Fix:
  reject out-of-range with 203.
- [x] 4.4 **[m]** Uncapped `values` in get_peers responses (`dht_handle.rs:148-167`)
  produces oversized datagrams. Fix: cap list length / respect a datagram budget.
- [x] 4.5 **[m]** Peer expiry 30 min vs BEP's suggested 45 (`dht_handle.rs:141-144`);
  expired peers / removed nodes never deleted from SQLite (unbounded growth).
- [x] 4.6 **[m]** `implied_port` treated as true only when == 1; BEP says non-zero
  (`message.rs:131-134`).
- [x] 4.7 **[m]** No `v` (client version) key in outgoing messages; no BEP 42 `ip` field.
- [x] 4.8 **[m]** Inbound fan-out uses `try_send` on 1024-deep channels — bursts silently
  drop routing updates and queries (`krpc_broker.rs:114-119`).

## Confirmed correct (do not "fix")

- KRPC envelope/keys (`t`/`y`/`q`/`a`/`r`/`e`), method arg names, error `[code, msg]`.
- Compact formats: 26-byte node info, 6-byte peer info, big-endian, both directions.
- XOR distance metric (`types.rs:45-60`); SQLite `xor()` ordering consistent with it.
- Token issue→require→203 flow shape and ~10-min acceptance window.
- BEP 42 self-id generation (`dht.rs:84-107`); bootstrap via ping + find_node(self).
- `implied_port` server-side semantics (origin IP/port selection).
- `get_peers` client accepts both `values` and `nodes` response forms.

## Suggested execution order

Tier 1 (panics) → Tier 2 items 2.1–2.3 (wrong answers) → Tier 3 items 3.1–3.2 (leaks) →
Tier 2 items 2.4–2.6 (lookup quality) → rest as time permits. Each tier ships with tests
and a green `cargo test -p midwest_mainline` gate.
